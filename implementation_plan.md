## Phase 1: Infrastructure & Data Layer (Backend)
**Goal:** Establish the SDE-3 database architecture. We already have Postgres (Prisma) and OAuth. Now we add Redis, MongoDB, BullMQ, and Cloudinary.

### 1. MongoDB (Unstructured Data)
- **Install:** `mongoose` in the Node server.
- **Implement:** A Mongoose schema for `ClinicalTranscript` and `DocumentOCR` to store the large, unstructured JSON data generated by the AI service.

### 2. Upstash Redis & Caching
- **Install:** `redis` and `ioredis` in the Node server.
- **Implement:** Redis connection manager. We will use this to cache repetitive API calls (e.g., fetching hospital details) and store WebSocket session states.

### 3. BullMQ & Resend (Queues & Emails)
- **Install:** `bullmq` and `resend`.
- **Implement:** A background worker queue for processing heavy tasks (like formatting the final doctor summary) and sending Email Notifications (OTP, Booking Confirmations).

### 4. Cloudinary (Media Storage)
- **Install:** `cloudinary` and `multer`.
- **Implement:** An upload middleware in Express to handle images of old prescriptions and send them to Cloudinary.

---

## Phase 2: State Management & Real-time (Frontend)
**Goal:** Upgrade the frontend state management to be ultra-optimized and real-time.

### 1. Redux Toolkit & RTK Query
- **Install:** `@reduxjs/toolkit` and `react-redux`.
- **Implement:** Replace standard `fetch/axios` calls with RTK Query endpoints for caching, invalidation, and automatic background refetching.

### 2. WebSockets (`socket.io`)
- **Implement:** Connect the frontend RTK state directly to Socket.io events. When the AI finishes processing a triage, the state will instantly update without a page reload.

---

## Phase 3: The Kiosk AI Engine (Python + Frontend)
**Goal:** Meet the exact SIH requirements for Voice, SOCRATES, and Document Upload.

### 1. The AI Prompts
- **Modify:** `ai-service/app/services/triage_agent.py` to strictly enforce the SOCRATES framework and AYUSH Dashavidha Pariksha modes.

### 2. Web Speech API
- **Modify:** `TriageChat.jsx` to use browser-native Speech Recognition (Voice-to-Text) and Speech Synthesis (Audio prompts).

### 3. Document Digitization
- **Implement:** Wire the Frontend Document Scanner to the Node.js Cloudinary uploader, which then forwards the URL to the FastAPI Gemini OCR endpoint.

---

## Phase 4: Physician Dashboards & Polish
**Goal:** The final touch for the judges.

- **Implement:** The Doctor Dashboard that receives the structured, WebSocket-driven summaries in real-time.
- **Polish:** Final UI review, error boundary implementation, and rate-limiting testing.
